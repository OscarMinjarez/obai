# Troubleshooting

Common issues and how to resolve them.

## Module Not Found errors in Backend
If you see errors like `Cannot find module 'obai/...'` when running the backend APIs:
1. **Ensure Webpack is enabled**: The backend now relies on Webpack to resolve monorepo aliases. Make sure you are using `npm run dev:apis` or `nest start` with the `--webpack` flag.
2. **Clean dist**: Sometimes old artifacts interfere. Run `rm -rf dist` (or `Remove-Item -Recurse -Force dist` in PowerShell) and restart.
3. **Prisma Generated Types**: If `generated/prisma` is missing, ensure you've run your prisma generate script.

## Import paths ending with `.ts`
If the editor reports: "An import path can only end with a '.ts' extension" — remove the `.ts` extension from imports. Example:
```ts
// good
import { useAuth } from '@obai/shared/composables/useAuth'
```

## i18n Locales Not Found
If the backend fails with an `I18nError`, check that your `i18n.module.ts` uses `process.cwd()` for the locales path. This ensures it works correctly within the Webpack bundle.

## Tailwind classes missing
Ensure each app's `tailwind.config.cjs` includes the shared paths:
```javascript
'../../libs/shared/src/**/*.{vue,js,ts,jsx,tsx}'
```
Also, ensure `libs/shared/tailwind.config.js` exists as it is required as a preset.

## TypeScript compiled files (.js, .map) in source dirs
If you see `.js` or `.js.map` files inside `apps/` or `libs/` folders:
1. These were likely generated by an accidental global `tsc` run.
2. Run the cleanup: `Get-ChildItem -Path "apps","libs" -Recurse -Include "*.js","*.js.map" | Remove-Item -Force`.
3. The projects are now configured with `noEmit: true` in their main tsconfigs to prevent this.
